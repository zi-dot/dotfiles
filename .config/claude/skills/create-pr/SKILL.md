# Create PR Skill

変更をコミット・プッシュしてPRを作成する自動化スキルです。

## 実行内容

以下の手順を自動で実行します:

1. **変更確認**: `git status` と `git diff` で変更内容を確認
2. **ステージング**: 変更されたファイルを `git add` でステージング
3. **コミット作成**:
   - 変更内容から適切なコミットメッセージを生成
   - 絵文字プレフィックスを付与
   - 日本語で簡潔に記述
4. **プッシュ**: リモートにプッシュ（必要に応じて `-u` オプション付き）
5. **PR作成**:
   - **Draft PRとして作成** (`--draft` オプション)
   - **assigneeに `zi-dot` を設定** (`--assignee zi-dot`)
   - タイトルはコミットメッセージと同様に絵文字付き日本語
   - 説明は以下のスタイルガイドに従う

## コミットメッセージの形式

```
{絵文字} [{カテゴリ}] {変更内容の簡潔な説明}
```

### 絵文字一覧

- 💚: E2Eテスト関連
- 🐛: バグ修正
- ✨: 新機能
- ♻️: リファクタリング
- 📝: ドキュメント
- 🎨: UIデザイン
- ⚡️: パフォーマンス改善
- 🔧: 設定ファイル

## PR説明の形式

```markdown
## Summary

[1〜2文：何をしたか + なぜやったか]

[変更の詳細を箇条書きで]
- メインポイント
  - 理由や補足
- メインポイント2

### 変更内容（大きめの PR の場合）

- **ファイル/機能名**: 何をしたか
- **ファイル/機能名**: 何をしたか

## References

- #123 または n/a
```

## PR説明のスタイルガイド

### 冒頭1〜2文（最重要）

- 「〜しました」「〜を追加しました」で締める
- 何を、なぜやったかが一発でわかるように
- 技術的な詳細は後回し

良い例:
- 「protoplugin ts_resource が生成する converter の FromProto 関数において、non-null assertion を廃止し、明示的な null チェックとエラーメッセージを追加しました。」
- 「ai-roleplay-csv-support の feature flag によって、「想定質問集」を CSV インポート・エクスポートする機能を追加しました。」

### 詳細説明

- 箇条書きの階層構造を使う
- 「なぜそうしたか」をサブポイントで添える
- 長文禁止、構造化を徹底

```markdown
- Windows 環境で Excel 操作が想定されるため BOM 付き UTF-8 でエクスポート
  - 二重 BOM 付与などは回避する
- インポートは Shift-JIS/UTF-8 の文字コードに対応しておく
  - Excel でローカル編集後、文字コードを引き継がない形でのファイル操作が多発されることが想定されるため
```

### 視覚的な工夫

- **太字**で重要キーワードをハイライト
- 表を使った構造化（設定値一覧など）
- Before/After のコード例で変更を明確に
- `> [!NOTE]` で補足情報を目立たせる

### 追加セクション（必要に応じて）

- `### 変更内容` - ファイル単位/機能単位の変更一覧
- `### 改善点` - この PR で何が良くなるか
- `### Before` / `### After` - 比較を明確にする
- `## Note` / `## Notes` - レビュアーに伝えたい補足
- `## Test plan` - テスト方法（チェックリスト形式）

### 避けるべきパターン

- だらだらした長文（常に箇条書きで構造化）
- 実装詳細の羅列だけ（必ず「なぜ」を添える）
- 冒頭での回りくどい説明
- References の省略（n/a でも書く）

## 注意事項

- コミットメッセージとPRタイトルは同じにする
